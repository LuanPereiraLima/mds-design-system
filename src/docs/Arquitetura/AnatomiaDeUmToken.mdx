# Anatomia de um token

## Formato DTCG

Os tokens-fonte em `tokens/` seguem o formato W3C DTCG: cada token é um
objeto com `$type` (a categoria — `color`, `dimension`, `string`,
`typography`, `shadow`...) e `$value` (o valor literal, ou um alias entre
chaves apontando pra outro token).

## Como um alias funciona, na prática

Em `01-brands/mrv/01-brand.mrv.tokens.json`, o papel `primary` não guarda um
hex — ele aponta pra uma chave do tema ativo:

```json
"primary": {
  "$type": "color",
  "$value": "{mrv.primary}"
}
```

Esse alias aponta pra dentro de `01-themes/light/01-theme.light.tokens.json`,
que por sua vez referencia o valor bruto em
`00-primitives/colors/00-primitive.raw.tokens.json` — um hex literal, sem mais
alias. Nenhum desses três arquivos guarda o valor final diretamente: ele só
existe depois que o Style Dictionary resolve a cadeia inteira e emite a CSS
custom property correspondente (`--primary`).

Os nomes dentro de `tokens/` **não são renomeados** — o pipeline só deriva a
convenção kebab-case das CSS custom properties a partir do mesmo `token.path`,
nunca hardcoda um nome.
