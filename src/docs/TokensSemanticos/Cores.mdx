# Cores

As cores são o fundamento mais impactante do MDS — alinhadas aos demais
tokens, são o que imprime identidade às marcas e produtos.

Cada swatch abaixo usa a CSS custom property real (`var(--token)`) da
marca/modo ativos — troque a **Marca** ou o **Modo** na toolbar e as cores
recalculam.

## Princípio central: posição e intenção

Toda a estrutura de cores do MDS segue a ideia de **posição e intenção no
layout**. Em vez de nomes de cor absolutos (como azul ou vermelho), o
sistema usa **papéis (roles)** — isso permite que a interface seja
adaptável entre marcas sem que o significado do token mude. Um
prefixo/sufixo consistente define a hierarquia de contraste e aplicação de
cada papel.

## Grupos de cor

- **Marca (visual)** — `primary`, `secondary`, `tertiary`, `complementary`:
  guiam a hierarquia de informação e as ações do usuário.
- **Estado (feedback)** — `attention`, `success`, `caution`, `critical`:
  padronizadas mentalmente pelos usuários para comunicar o resultado de uma
  ação ou o status de um sistema.
- **Neutras** — `background`, `surface`, `outline`, `shadow`: base dos
  layouts e agrupamento de conteúdos (cards, modais, painéis).
- **Inversas** — usadas para elementos que precisam romper a hierarquia
  visual comum, gerando um forte contraste.

Todos esses papéis são emitidos por marca × modo em
`src/tokens/css/<marca>.<modo>.css`, escopados em
`[data-brand][data-theme]`. A descrição sob cada swatch vem do handoff de
conteúdo do design (ver `src/docs/lib/descriptions.ts`).

> ℹ️ A entrega também traz a coleção `02-interface`, que reexporta a paleta
> inteira como um checkpoint brand-agnóstico. Ela ainda **não** é emitida em
> CSS pelo build — os componentes consomem os papéis diretamente.
